# Convex Backend (self-hosted) Implementation Plan — Plan 2a

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up a self-hosted Convex backend in the existing docker-compose stack, define the user-centric schema (user, preferences, basket, grocery list), and implement the functions that manage the basket and generate + check off the grocery list — including the `generateGroceryList` action that calls the Go `recipe-service` over the compose network.

**Architecture:** Convex is added as a workspace package `packages/convex` (`@pantry/convex`) holding the `convex/` functions and the generated API. Self-hosted Convex (backend + dashboard) runs as services in the repo-root `docker-compose.yml`, on the same network as `recipe-service` so the `generateGroceryList` action can reach it at `http://recipe-service:8080`. Convex stays user-centric: it stores the basket (references to recipe ids + denormalized title) and the live grocery list, never recipe bodies. No web app in this plan — everything is verified with `pnpm exec convex run` against the live self-hosted backend.

**Tech Stack:** Convex (self-hosted, `ghcr.io/get-convex/convex-backend` + `convex-dashboard`), TypeScript, pnpm workspace, the existing Go `recipe-service` + Postgres + Docker Compose.

## Global Constraints

- Convex package is `@pantry/convex` at `packages/convex`, with the `convex/` functions folder beside its `package.json`. Use **pnpm** (`pnpm --filter @pantry/convex add convex`). Run the CLI as `pnpm exec convex …` from `packages/convex`.
- Self-hosted Convex CLI config lives in `packages/convex/.env.local` (gitignored): `CONVEX_SELF_HOSTED_URL=http://127.0.0.1:3210` and `CONVEX_SELF_HOSTED_ADMIN_KEY=<generated>`. Never commit the admin key.
- Convex backend listens on `3210` (API) and `3211` (HTTP actions); dashboard on `6791`. These services live in the **repo-root `docker-compose.yml`** (same compose project/network as `recipe-service`), NOT a separate compose file.
- **No recipe bodies in Convex.** The basket stores `{ userId, recipeId, title }`; the grocery list stores aggregated lines. Recipe definitions stay in `recipe-service`.
- Auth is stubbed: a single constant `DEV_USER_ID = "dev-user"` (matches the Go service's `DevUserID`). Every Convex row is scoped by `userId`. No login.
- The `generateGroceryList` action reaches the Go service via a Convex deployment env var `RECIPE_SERVICE_URL` (set to `http://recipe-service:8080` for the in-network path). It calls `POST {RECIPE_SERVICE_URL}/grocery-list` with `{ recipeIds }` and persists the returned `[{item,unit,quantity}]` lines.
- The grocery-list aggregation logic itself is NOT reimplemented in Convex — it is delegated to `recipe-service` (the canonical owner). Convex only orchestrates and stores.

## Task 3: Basket functions (list / add / remove)

**Files:**
- Create: `packages/convex/convex/basket.ts`

**Interfaces:**
- Consumes: `DEV_USER_ID`, the `basket` table.
- Produces:
  - `query list()` → basket items for the dev user `[{_id, recipeId, title}]`
  - `mutation add({ recipeId, title })` → inserts (idempotent: if `(userId, recipeId)` already present, does nothing) → returns the item id
  - `mutation remove({ recipeId })` → deletes the dev user's basket row for that recipe

- [ ] **Step 1: Implement the basket functions**

`packages/convex/convex/basket.ts`:
```ts
import { query, mutation } from "./_generated/server";
import { v } from "convex/values";
import { DEV_USER_ID } from "./constants";

export const list = query({
  args: {},
  handler: async (ctx) => {
    return await ctx.db
      .query("basket")
      .withIndex("by_user", (q) => q.eq("userId", DEV_USER_ID))
      .collect();
  },
});

export const add = mutation({
  args: { recipeId: v.string(), title: v.string() },
  handler: async (ctx, { recipeId, title }) => {
    const existing = await ctx.db
      .query("basket")
      .withIndex("by_user_recipe", (q) =>
        q.eq("userId", DEV_USER_ID).eq("recipeId", recipeId),
      )
      .unique();
    if (existing) return existing._id;
    return await ctx.db.insert("basket", { userId: DEV_USER_ID, recipeId, title });
  },
});

export const remove = mutation({
  args: { recipeId: v.string() },
  handler: async (ctx, { recipeId }) => {
    const existing = await ctx.db
      .query("basket")
      .withIndex("by_user_recipe", (q) =>
        q.eq("userId", DEV_USER_ID).eq("recipeId", recipeId),
      )
      .unique();
    if (existing) await ctx.db.delete(existing._id);
  },
});
```

## Task 4: generateGroceryList action + grocery-list queries/mutations

**Files:**
- Create: `packages/convex/convex/groceryList.ts`
- Create: `packages/convex/convex/recipes.ts`

**Interfaces:**
- Consumes: `DEV_USER_ID`, the `basket` + `groceryList` tables, `RECIPE_SERVICE_URL` deployment env var, the existing `recipe-service` `POST /grocery-list`.
- Produces:
  - `query getGroceryList()` → the dev user's grocery lines `[{_id,item,unit,quantity,checked}]`
  - `internalMutation replaceGroceryList({ lines })` → deletes the dev user's existing lines and inserts the new aggregated lines (`checked: false`)
  - `mutation toggleItem({ id, checked })` → sets `checked` on one line
  - `action generateGroceryList()` → reads basket recipe ids, `POST`s them to `recipe-service`, writes the result via `replaceGroceryList`

- [ ] **Step 1: Implement the grocery-list queries/mutations**

`packages/convex/convex/groceryList.ts`:
```ts
import { query, mutation, internalMutation } from "./_generated/server";
import { v } from "convex/values";
import { DEV_USER_ID } from "./constants";

export const getGroceryList = query({
  args: {},
  handler: async (ctx) => {
    return await ctx.db
      .query("groceryList")
      .withIndex("by_user", (q) => q.eq("userId", DEV_USER_ID))
      .collect();
  },
});

export const replaceGroceryList = internalMutation({
  args: {
    lines: v.array(
      v.object({ item: v.string(), unit: v.string(), quantity: v.number() }),
    ),
  },
  handler: async (ctx, { lines }) => {
    const existing = await ctx.db
      .query("groceryList")
      .withIndex("by_user", (q) => q.eq("userId", DEV_USER_ID))
      .collect();
    for (const row of existing) await ctx.db.delete(row._id);
    for (const line of lines) {
      await ctx.db.insert("groceryList", {
        userId: DEV_USER_ID,
        item: line.item,
        unit: line.unit,
        quantity: line.quantity,
        checked: false,
      });
    }
  },
});

export const toggleItem = mutation({
  args: { id: v.id("groceryList"), checked: v.boolean() },
  handler: async (ctx, { id, checked }) => {
    await ctx.db.patch(id, { checked });
  },
});
```

- [ ] **Step 2: Implement the generateGroceryList action**

`packages/convex/convex/recipes.ts`:
```ts
import { action } from "./_generated/server";
import { internal } from "./_generated/api";

type GroceryLine = { item: string; unit: string; quantity: number };

// Reads the basket, asks recipe-service to aggregate those recipes into a
// grocery list, and persists the result as the reactive grocery list.
// The aggregation lives in recipe-service (the canonical owner); Convex only
// orchestrates and stores. No recipe bodies are stored here.
export const generateGroceryList = action({
  args: {},
  handler: async (ctx): Promise<{ count: number }> => {
    const baseUrl = process.env.RECIPE_SERVICE_URL;
    if (!baseUrl) throw new Error("RECIPE_SERVICE_URL is not set on the deployment");

    const basket = await ctx.runQuery((await import("./_generated/api")).api.basket.list, {});
    const recipeIds = basket.map((b: { recipeId: string }) => b.recipeId);

    const res = await fetch(`${baseUrl}/grocery-list`, {
      method: "POST",
      headers: { "content-type": "application/json" },
      body: JSON.stringify({ recipeIds }),
    });
    if (!res.ok) {
      throw new Error(`recipe-service /grocery-list failed: ${res.status}`);
    }
    const lines = (await res.json()) as GroceryLine[];

    await ctx.runMutation(internal.groceryList.replaceGroceryList, { lines });
    return { count: lines.length };
  },
});
```
Note on the `api`/`internal` imports: actions reference other functions via the generated `api`/`internal` objects. If your installed Convex version prefers a top-level `import { api, internal } from "./_generated/api"`, use that for both (replace the inline dynamic import for `api.basket.list` with the top-level `api`). Keep `internal.groceryList.replaceGroceryList` for the internal mutation. Verify the exact reference style against `_generated/api.d.ts` after codegen.
